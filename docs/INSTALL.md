# 安装与适配

## 基础环境

这份快照适配 AstrBot 4.29.3。QQ 拓展的元数据要求 `>=4.29.0,<5.0.0`，其他版本请先验证。启动与数据目录由你自己的安装方式决定，不要求存在维护者的 D 盘路径。

推荐逐个安装，保留已有配置副本。Release 的单插件 ZIP 各自包含插件根目录与 `main.py`。源码方式安装时，把 `plugins/` 下的目录分别复制到自己的插件目录，不要把合集整个当作一个插件。

## Provider ID 对应关系

Provider ID 是你在 AstrBot 中创建的配置名称，不等于厂商模型名称。以下对应关系必须自己设置：

| 用途 | 配置位置 | 要求 |
| --- | --- | --- |
| 普通聊天 | AstrBot 的聊天模型提供商 | 可用的聊天模型 |
| 记忆提取 | LivingMemory → 模型设置 → LLM Provider ID | 你自己的聊天 Provider ID |
| 记忆检索索引 | LivingMemory → 模型设置 → Embedding Provider ID | 真正的嵌入模型，不是普通聊天模型 |
| 表情描述/图片识别 | 表情包管理器 → 语义化、自动收集的视觉模型设置 | 支持图片输入的模型 |
| 语义选图 | 表情包管理器 → 辅助模型设置，以及语义索引的 Embedding 设置 | 按自己的 Provider 名称设置 |
| 情绪判断 | LivingMemory → 情绪设置 | 可独立选择，留空按插件规则回退 |

本地 Ollama 仅提供嵌入模型时，聊天仍由云端 Provider 完成。此前这套适配使用过 `qwen3-embedding:4b`；这只是组合示例，并非唯一选择。必须让 Ollama 服务可连接。改变嵌入模型后需要按插件流程重建索引，不能把不同维度混用。

## 插件配合

- **LivingMemory** 是记忆、情绪、目的背景、费用和节奏的底座。启用后先确认模型配置与初始化状态。
- **Proactive Chat** 负责私聊主动消息的发送时机和免打扰。QQ 拓展产生的话题复用该流程。
- **meme_manager** 负责唯一一份表情收集与语义索引。QQ 拓展只在确认收集成功后提供可选互动；它不会再建一套表情库。
- **QQ 拓展** 需要可用的 aiocqhttp/NapCat 连接。主人范围请自行填写或按插件规则从自己的白名单解析。更换账号时必须重新核对。
- **CloneTTS** 填自己的火山 API Key 和已复刻的音色 ID。需要开通相应的声音复刻服务；是否有免费额度以自己的控制台为准。
- **小鱼唱歌** 默认使用云端 `doubao`。可在配置中复用 CloneTTS 的凭据与音色，但声音复刻字符额度不等于唱歌音频生成额度；音色跨服务是否可用以服务返回为准。唱歌需要另外开通音频生成服务。

本地 SoulX 是可选后端，安装脚本会下载独立的模型和环境。分享包不包括参考声音及其时间/音高标注；请自行准备有使用权的 `prompt.wav` 和配套 `prompt.json`。默认云端唱歌不依赖这些文件。

## 关于配置模板

`examples/*_config.example.json` 来自源码 schema 的默认值，不含维护者实际账号、人格和偏好。普通插件在 WebUI 里配置即可，无需手工导入模板。QQ 拓展公开副本的默认数据目录为空，交由 AstrBot 的插件数据目录处理。

不要把凭据写进源代码或推送到 Git。填写凭据应在你自己的 AstrBot 配置界面完成。安装包不包含维护者的试用余额、音色权限、表情资源或历史记忆。

## 已知边界

- 这是源码快照，不承诺所有不同版本的 AstrBot、NapCat、云端接口与操作系统都已实测。
- QQ/空间能力受实际登录账号可见权限和 NapCat/API 支持限制。读取失败不能当作读过了全文。
- 云端唱歌支持更多歌名和主题，但可能即兴改变旋律，不能保证还原任意原曲。
- 费用统计是用量核算；余额查询/校准和资源包记录存在平台差异，不是账户全部消费的自动总账。
- 新消息优先转接保留已经发出的消息，停止旧轮未发出的尾句；语音、工具调用和带实际操作确认的回复保留各自流程。模型生成和网络发送本身仍需要时间。
